# Feed Service — Сервис формирования ленты публикаций

**Feed Service** — это сервис, отвечающий за формирование ленты публикаций. Он не создаёт публикации напрямую, а получает сообщения о новых публикациях из других сервисов (например, `user-service`, `society-service`) через Kafka. На основе этих событий формируется база данных для построения ленты рекомендаций.

## Какие бывают публикации

Публикации бывают разных типов:

- **Посты пользователей** — приходят из `user-service`
- **Статьи сообществ** — приходят из `society-service`
- Возможны и другие типы, если их создают дополнительные сервисы

Каждый сервис сам создаёт публикации и хранит их содержимое. У публикаций из разных сервисов может быть разная структура. **Feed Service** только получает сообщение о том, что публикация создана, и сохраняет соответствующую метаинформацию у себя.

## Структура базы данных

База данных Feed Service содержит две основные таблицы:

- `entities`  
  Хранит:
    - `external_uuid` — `uuid` публикации в исходном сервисе
    - `service_name` — название сервиса, где была создана публикация

- `entities_suggestion`  
  Хранит:
    - `post_uuid` — ссылка на публикацию из `entities`
    - `target_uuid` — `uuid` пользователя, которому рекомендуется эта публикация

## Как работает формирование ленты

1. Приходит запрос в сервис на создание ленты с `uuid` пользователя.
2. По таблице `entities_suggestion` находятся все `post_uuid`, рекомендованные этому пользователю.
3. Для каждой публикации запрашиваются полные данные из соответствующего сервиса (например, `user-service`, `society-service`) по `external_uuid`.
4. Готовая лента собирается из полной информации публикаций и отправляется на `frontend`.

## Как работает система рекомендаций

- Когда пользователь создаёт публикацию, она автоматически **рекомендуется всем его подписчикам**.
- В `entities_suggestion` создаются соответствующие записи для каждого подписчика.
- Приоритет у новых публикаций — рекомендации сортируются по времени создания.

## Как добавить поддержку новых видов публикаций

Чтобы `Feed Service` мог принимать и обрабатывать публикации из нового сервиса, нужно:

1. **Создать consumer** для Kafka-топика нового сервиса:
  - Файл размещается в директории с названием сервиса (например `user` для `user-service`) в `cmd/workers`

2. **Добавить вызов handler'а** в handler `GetPost` для получения полной информации о публикации:
  - handler `GetPost` находится в `internal/service/service.go`
